# Feature Specification: RAG 问答系统增强

**Feature Branch**: `003-rag-qa-enhancement`  
**Created**: 2026-03-19  
**Status**: Draft  
**Input**: User description: "将推荐系统升级为问答系统，加入重排和生成步骤，改善低质量样本匹配时的用户体验"

## Clarifications

### Session 2026-03-19

- Q: 生成回答使用什么技术方案？ → A: OpenAI GPT API（GPT-4o-mini 或 GPT-4o）
- Q: 重排机制使用什么方法？ → A: 交叉编码器（bge-reranker-base）
- Q: 低质量匹配的相似度阈值是多少？ → A: 0.5
- Q: 样本数据质量评估的标准是什么？ → A: 字段完整性评估，缺失字段的样本仍可使用已有数据（降权而非排除）
- Q: 生成回答的最大长度限制是多少？ → A: 300-500 字

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 自然语言问答 (Priority: P1)

用户输入关于 SSBR 官能化的问题，系统不仅返回相关样本列表，还基于检索到的样本内容生成一段专业、连贯的自然语言回答，直接解答用户问题。

**Why this priority**: 这是从"推荐系统"升级为"问答系统"的核心功能，直接提升用户体验和系统专业度。用户不再需要自行阅读多个样本文档来获取答案。

**Independent Test**: 可通过输入一个典型问题（如"如何改善白炭黑分散性？"）并验证系统返回包含具体建议、数据支撑和文献引用的自然语言回答来测试。

**Acceptance Scenarios**:

1. **Given** 用户输入"如何改善白炭黑分散性？", **When** 系统完成检索和生成, **Then** 返回一段包含官能化建议、性能数据和文献来源的专业回答
2. **Given** 用户输入技术性问题, **When** 检索到多个相关样本, **Then** 回答综合多个样本的信息，而非简单罗列
3. **Given** 用户输入问题, **When** 系统生成回答, **Then** 回答中明确标注数据来源（样本ID或文献DOI）

---

### User Story 2 - 重排优化检索精度 (Priority: P2)

系统在初步向量检索后，对 Top-K 候选结果进行重排序，将最相关的样本排在前面，提高检索精度。

**Why this priority**: 重排步骤可显著提升检索质量，确保生成回答基于最相关的样本，减少"答非所问"的情况。

**Independent Test**: 可通过对比有/无重排时的检索结果排序，验证重排后更相关的样本排名更靠前。

**Acceptance Scenarios**:

1. **Given** 初步检索返回 10 个候选样本, **When** 执行重排, **Then** 最相关的 3-5 个样本被提升到前列
2. **Given** 用户查询与某样本高度相关, **When** 该样本在初步检索中排名靠后, **Then** 重排后该样本排名显著提升
3. **Given** 重排完成, **When** 查看最终结果, **Then** 结果按重排后的相关性分数排序

---

### User Story 3 - 低质量匹配的优雅处理 (Priority: P2)

当所有检索结果的相似度都较低（低于阈值）时，系统不直接显示"未找到相关结果"，而是给出专业的引导性回答，包括：可能的原因分析、相关领域的一般性建议、以及如何调整查询的提示。

**Why this priority**: 直接提升用户体验，避免用户在匹配到低质量样本时感到系统"不专业"或"无用"。

**Independent Test**: 可通过输入一个与现有样本无关或关系较远的查询，验证系统返回有帮助的引导性回答而非简单的"未找到"提示。

**Acceptance Scenarios**:

1. **Given** 用户输入与现有样本关联度低的查询, **When** 所有结果相似度 < 0.5, **Then** 系统返回专业的引导性回答
2. **Given** 低相似度匹配场景, **When** 系统生成回答, **Then** 回答包含：问题分析、通用建议、查询优化提示
3. **Given** 系统检测到低质量匹配, **When** 仍有部分相关样本, **Then** 回答明确告知"以下信息仅供参考"并说明局限性

---

### User Story 4 - 保留原有推荐列表功能 (Priority: P3)

在生成自然语言回答的同时，系统仍展示相关样本列表，用户可查看每个样本的详细信息。问答和推荐两种模式可切换或并存。

**Why this priority**: 保持向后兼容，部分用户可能仍需要直接浏览样本详情，而非只看生成的回答。

**Independent Test**: 可通过同一查询验证系统同时返回生成回答和样本列表两部分内容。

**Acceptance Scenarios**:

1. **Given** 用户执行查询, **When** 系统返回结果, **Then** 页面同时展示生成回答和相关样本列表
2. **Given** 用户查看结果, **When** 点击某个样本, **Then** 可展开查看该样本的完整详情
3. **Given** 用户偏好不同展示方式, **When** 切换显示模式, **Then** 可选择只看回答、只看列表、或两者都看

---

### Edge Cases

- 当检索结果为空（没有任何相关样本）时，系统应提供通用的领域知识回答，而非报错
- 当用户输入非技术性问题（如"你好"）时，系统应友好回应并引导用户输入技术问题
- 当生成回答过程出现异常时，系统应回退到只展示推荐列表模式
- 当单个样本数据不完整或质量差时，生成回答时应降低该样本的权重或跳过

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 使用 OpenAI GPT API（GPT-4o-mini 或 GPT-4o）基于 Top-K 相关样本内容生成自然语言回答，回答长度控制在 300-500 字
- **FR-002**: 系统 MUST 在生成回答中标注数据来源（样本 ID、文献 DOI 或引文）
- **FR-003**: 系统 MUST 使用交叉编码器（bge-reranker-base）对初步检索的候选样本进行重排序
- **FR-004**: 系统 MUST 在所有结果相似度低于 0.5 时，生成专业的引导性回答
- **FR-005**: 系统 MUST 同时支持问答模式和推荐列表模式
- **FR-006**: 系统 MUST 在生成回答时综合多个相关样本的信息，而非只使用单一样本
- **FR-007**: 系统 MUST 在引导性回答中包含：问题分析、通用建议、查询优化提示
- **FR-008**: 系统 MUST 基于字段完整性对样本质量进行评估，对缺失字段的样本采用降权策略（仍使用已有数据，而非排除）
- **FR-009**: 系统 MUST 保持回答的专业性和准确性，禁止编造不存在的数据
- **FR-010**: 系统 MUST 在回答中明确区分"基于文献数据"和"一般性建议"

### Key Entities

- **Query（查询）**: 用户输入的自然语言问题，包含意图和关键词
- **Candidate（候选样本）**: 初步检索返回的样本集合，包含样本 ID、相似度分数、内容摘要
- **RankedResult（重排结果）**: 经过重排后的样本列表，包含重排分数和排名
- **GeneratedAnswer（生成回答）**: 系统生成的自然语言回答，包含回答文本、引用来源、置信度
- **QualityScore（质量分数）**: 基于字段完整性的样本数据评估分数，用于生成回答时的权重调整（缺失字段降权但不排除）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户获得完整回答的时间不超过 5 秒（从提交查询到显示生成回答）
- **SC-002**: 生成回答的引用准确率达到 100%（所有引用数据可追溯到具体样本）
- **SC-003**: 重排后 Top-3 结果的相关性评分比重排前提升至少 20%
- **SC-004**: ~~低质量匹配场景下，用户满意度（通过反馈机制收集）不低于 70%~~ *[延后评估：需运营阶段收集用户反馈]*
- **SC-005**: ~~系统在无高相关样本时，仍能提供有价值的引导信息，用户二次查询成功率提升 50%~~ *[延后评估：需使用日志分析]*
- **SC-006**: 生成回答覆盖查询中 80% 以上的核心问题点

## Assumptions

- 现有的 82 个 summary.md 文档质量足以支撑问答生成
- 用户查询主要围绕 SSBR 官能化、白炭黑分散、轮胎性能等专业领域
- 系统可通过现有 OpenAI Embedding 服务进行向量检索，同一 API 可用于生成回答
- 交叉编码器（bge-reranker-base）可在合理时间（<1秒）内完成重排处理
- 低质量样本可通过 summary.md 中 YAML front matter 的字段完整性进行识别
- GPT-4o-mini 可在 3 秒内生成 300-500 字的专业回答

## Out of Scope

- 多轮对话和上下文记忆（本期只做单轮问答）
- 用户反馈的自动学习和模型优化
- 实时爬取外部文献补充知识库
- 语音输入/输出功能
