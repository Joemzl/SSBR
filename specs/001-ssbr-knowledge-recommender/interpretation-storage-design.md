# 解读数据存储架构设计

**Date**: 2026-03-04 | **Branch**: `001-ssbr-knowledge-recommender`

## 背景与问题

### 当前架构的局限

1. **按列存储解读结果**：每种表征类型占用一列，扩展性差
2. **长文本存储问题**：Excel 单元格不适合存储长文本解读
3. **检索效率低**：无法进行语义检索，只能精确匹配关键词
4. **多图谱混合问题**：K列（核心力学图谱）可能包含多种类型（应力-应变/Payne/DMA）

### 推荐系统的需求

作为 RAG 风格的推荐系统，需要：
- 根据用户需求的**语义相似度**匹配历史案例
- 支持**多维度检索**（官能团、性能指标、应用场景）
- 能够**追溯解读来源**（哪篇文献、哪个图表）
- 支持**增量更新**（新增表征类型无需修改结构）

## 推荐方案：双层存储架构

```
┌─────────────────────────────────────────────────────────────┐
│                    查询层 (Query Layer)                       │
│   用户输入：我需要一种能提高白炭黑分散性的 SSBR 官能化方案            │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                 向量检索层 (Vector Search)                    │
│   1. 语义相似度匹配解读文档                                      │
│   2. 返回 Top-K 相关样本 ID                                    │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                结构化数据层 (Structured Data)                  │
│   根据样本 ID 获取完整信息：                                     │
│   - 官能化配方（试剂、程度）                                     │
│   - 性能指标（力学、热学）                                       │
│   - 文献来源（DOI、引文）                                       │
└─────────────────────────────────────────────────────────────┘
```

# 力学性能解读：SSBR-001

## 图谱类型
应力-应变曲线

## 核心发现

### 1. 模量增强效果
- **初始模量**：官能化样品（3.8 MPa）vs 未改性样品（2.4 MPa），提升 58%
- **300%定伸应力**：9.2 MPa vs 6.7 MPa，提升 37%
- **机理**：三乙氧基硅烷基与白炭黑表面-OH形成共价键，增强界面结合

### 2. 强度与韧性平衡
- **拉伸强度**：15.6 MPa，保持在优秀水平
- **断裂伸长率**：452%，略有降低但仍满足应用需求
- **评价**：在增强模量的同时保持了良好的韧性

## 关键指标

| 指标 | 数值 | 对比未改性 | 变化 |
|------|------|-----------|------|
| 100%定伸应力 | 1.5 MPa | 1.0 MPa | +50% |
| 300%定伸应力 | 9.2 MPa | 6.7 MPa | +37% |
| 拉伸强度 | 15.6 MPa | 14.2 MPa | +10% |
| 断裂伸长率 | 452% | 520% | -13% |

## 应用建议

该官能化方案适用于需要**高模量、耐磨损**的应用场景，如轮胎胎面。

sample_id: SSBR-001

SSBR-001 采用 3-氨丙基三乙氧基硅烷进行巯基-烯点击化学改性，官能化程度 3.6 wt%。
该方案显著提升了橡胶/白炭黑界面相互作用，表现为：
- TEM显示白炭黑分散性显著改善，团聚体尺寸减小
- Payne效应ΔG'降低，表明填料网络强度下降、分散更均匀
- 静态力学：模量提升50%+，拉伸强度略有提升，断裂伸长率小幅下降
- DMA：60℃ tanδ降低，预示滚动阻力降低；0℃ tanδ保持，湿地抓地力不受影响
该官能团通过与白炭黑形成化学键合，实现了"低滚阻-高抓地"的性能平衡，适用于绿色轮胎胎面。

#### 优点

1. **灵活性高**：新增表征类型只需创建新文件
2. **版本可控**：Git 可追踪解读变更
3. **检索友好**：Markdown 文本易于被向量化
4. **人类可读**：直接打开 Markdown 查看解读

### 方案 B：SQLite + 向量扩展（中等复杂度）

如果样本量增长到数百条以上，可考虑使用 SQLite + sqlite-vec 扩展：

```sql
-- 解读文档表
CREATE TABLE interpretations (
    id INTEGER PRIMARY KEY,
    sample_id TEXT NOT NULL,           -- 外键关联到 Excel 样本
    type TEXT NOT NULL,                -- 'nmr', 'tem', 'mechanical', 'dsc', 'summary'
    content TEXT NOT NULL,             -- Markdown 格式解读内容
    source_figure TEXT,                -- 来源图注
    source_doi TEXT,                   -- 来源 DOI
    skill_used TEXT,                   -- 使用的 Skill
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(sample_id, type)
);

-- 向量索引表（使用 sqlite-vec）
CREATE VIRTUAL TABLE interpretation_embeddings USING vec0(
    embedding float[1536]              -- OpenAI ada-002 维度
);
```

| `4/4+S` | 全部解读 + 综合摘要完成 |

## 推荐系统查询流程

### 用户输入

```
我需要一种能提高白炭黑分散性、同时降低滚动阻力的 SSBR 官能化方案
```

### 查询流程

```
1. [语义检索] 对 /dataset/interpretations/*/summary.md 进行向量相似度搜索
   ↓
2. [Top-K 匹配] 返回相似度最高的 5 个样本 ID：
   - SSBR-001 (相似度: 0.92)
   - SSBR-005 (相似度: 0.88)
   - SSBR-012 (相似度: 0.85)
   ↓
3. [结构化查询] 从 Excel 获取这 5 个样本的详细信息：
   - 官能化试剂、程度
   - 力学/热学性能指标
   - 文献来源
   ↓
4. [深度解读] 按需加载具体解读文档：
   - /interpretations/SSBR-001/tem.md → TEM 分散性解读
   - /interpretations/SSBR-001/mechanical.md → DMA 滚阻相关解读
   ↓
5. [推荐输出] 生成推荐报告
```

## 实施路径

### Phase 1：建立文件结构（立即执行）

1. 创建 `/dataset/interpretations/` 目录
2. 为现有 17 个样本创建文件夹
3. 定义统一的 Markdown 模板

### Phase 2：更新 Skills 输出格式

1. 修改各解读 Skill，输出时自动保存到对应文件
2. 添加 YAML front matter 元数据
3. 生成 summary.md 综合摘要

### Phase 3：实现向量化检索（可选）

1. 使用 OpenAI Embeddings 或本地模型生成向量
2. 存储到向量数据库（如 Chroma、Milvus 或 sqlite-vec）
3. 集成到推荐系统查询接口

## 对比总结

| 方案 | 存储方式 | 检索方式 | 扩展性 | 实现复杂度 |
|------|----------|----------|--------|------------|
| **现状** | Excel 列 | 精确匹配 | ❌ 差 | 低 |
| **方案 A（推荐）** | 文件系统 | 向量 + 文件检索 | ✅ 优 | 中 |
| **方案 B** | SQLite | 向量 + SQL | ✅ 优 | 中高 |
| **方案 C** | PostgreSQL + pgvector | 向量 + SQL | ✅ 优 | 高 |

**推荐**：先采用方案 A（文件系统），当样本量超过 100 条时再考虑迁移到数据库。
