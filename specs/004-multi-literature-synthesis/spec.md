# Feature Specification: 多文献综合推理问答系统

**Feature Branch**: `004-multi-literature-synthesis`  
**Created**: 2026-03-24  
**Status**: Draft  
**Input**: User description: "我想做一次大的改进：当前问答系统给出的结果其实也是某一条数据库中的样本，我想让问答系统可以综合多篇文献给出结果，最后的答案甚至可以不是某条数据样本的内容，即我需要一些外推能力！"

## Clarifications

### Session 2026-03-24

- Q: 外推边界如何定义？ → A: 保守外推——允许外推至数据范围外 50%（如数据覆盖 1%-15%，可外推到 0.5%-22.5%），超出则拒绝并说明原因
- Q: 综合回答采用什么输出结构？ → A: 分层结构——先给结论摘要（2-3句），再分点展开支撑证据和来源
- Q: 多文献数据矛盾时如何处理？ → A: 展示分歧——明确列出不同数据及来源，分析可能的差异原因（如实验条件、样本配方不同）
- Q: 外推预测的置信度如何表达？ → A: 定性等级+数据支撑——使用三级标签（高/中/低置信度）并说明基于多少个数据点（如"中等置信度，基于 4 个相近样本"）
- Q: 综合分析的最小样本数要求？ → A: 分层要求——对比分析最少 2 个样本，趋势分析/外推最少 3 个样本

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 多文献综合回答 (Priority: P1)

用户提出一个技术问题，系统不再局限于返回单个最匹配的样本，而是**综合分析多篇文献的数据和结论**，生成一个整合性的回答。回答融合来自多个样本的知识，给出比任何单一样本更全面的见解。

**Why this priority**: 这是核心需求——从"样本检索"升级为"知识综合"。当前系统本质上是在已有样本中找最像的那个，无法产生新见解。综合多文献能大幅提升问答的实用价值。

**Independent Test**: 输入"如何同时改善白炭黑分散性和湿地抓地力？"，验证回答综合了多个使用不同官能团的样本经验，而非只返回单一方案。

**Acceptance Scenarios**:

1. **Given** 用户询问"如何改善白炭黑分散性？", **When** 系统检索到 5 个使用不同官能团的相关样本, **Then** 回答综合比较多种官能团方案的优缺点，而非只推荐单一方案
2. **Given** 用户询问复合性能需求（如兼顾分散和抓地力）, **When** 不同样本分别在不同指标上表现优异, **Then** 回答综合分析各方案的取舍，给出平衡建议
3. **Given** 系统生成综合回答, **When** 用户查看回答, **Then** 回答明确标注每个建议或数据点的来源文献

---

### User Story 2 - 知识外推与趋势分析 (Priority: P1)

基于多个样本的数据，系统能够**识别规律并进行合理外推**。例如：根据官能化程度与性能的关系数据，推断出某个未测试的官能化程度可能达到的性能区间。

**Why this priority**: 这是用户明确要求的"外推能力"——答案不局限于已有数据点，而是基于数据规律给出预测性建议。这是从"查询"到"分析"的质变。

**Independent Test**: 询问"官能化程度在 5% 左右时，拉伸强度大概是多少？"，验证系统能基于现有 3%、8%、10% 等数据点给出合理的插值/外推估计。

**Acceptance Scenarios**:

1. **Given** 用户询问某个未覆盖的官能化程度的预期性能, **When** 数据库中有相近官能化程度的样本数据, **Then** 系统基于数据趋势给出合理的估计区间，并明确标注为"外推估计"
2. **Given** 用户询问"官能化程度和分散性的关系", **When** 系统分析多个样本数据, **Then** 回答总结出趋势规律（如"官能化程度每增加 1%，Payne 效应降低约 X%"）
3. **Given** 系统进行外推预测, **When** 数据支撑不足（样本数 < 3 或相关性弱）, **Then** 回答明确声明不确定性，避免过度自信的预测

---

### User Story 3 - 配方设计建议 (Priority: P2)

用户描述目标性能需求（如"我需要一个湿抓好、滚阻低的胎面配方"），系统基于多文献知识，**主动设计一个组合方案**，包括官能团选择、官能化程度推荐、填料用量建议等。

**Why this priority**: 这是综合能力的高阶应用——从"分析已有"到"设计新方案"。需要 P1 的综合和外推能力作为基础。

**Independent Test**: 输入"设计一个高湿地抓地力、低滚动阻力的配方"，验证系统给出包含具体官能团、程度、填料等参数的配方建议。

**Acceptance Scenarios**:

1. **Given** 用户描述目标性能需求, **When** 系统分析需求, **Then** 返回一个包含官能团类型、官能化程度、填料体系的综合配方建议
2. **Given** 系统生成配方建议, **When** 建议基于多个样本经验, **Then** 每个参数选择都附带理由和文献支撑
3. **Given** 用户目标存在内在矛盾（如同时要求极高强度和极高伸长率）, **When** 系统分析后发现, **Then** 回答明确指出矛盾，并给出最佳折中方案

---

### User Story 4 - 对比分析表格 (Priority: P3)

用户询问多种方案的对比（如"羟基和羧基官能化哪个更好？"），系统生成结构化的对比表格，从多个维度（性能、成本、工艺难度等）比较不同方案。

**Why this priority**: 对比分析是常见需求，表格形式便于用户快速决策。优先级较低是因为这本质上是 P1 综合能力的一种输出格式。

**Independent Test**: 询问"羟基和环氧官能化的区别"，验证系统返回包含力学性能、热学性能、分散效果等维度的对比表格。

**Acceptance Scenarios**:

1. **Given** 用户询问两种或多种方案的对比, **When** 系统检索到相关样本, **Then** 返回结构化对比表格，包含各方案在不同维度的表现
2. **Given** 对比涉及的某个维度数据缺失, **When** 生成表格, **Then** 相应单元格标注"数据不足"而非编造数据
3. **Given** 用户未指定对比维度, **When** 系统生成对比, **Then** 自动选择最相关的 5-7 个核心维度

---

### Edge Cases

- 当检索到的样本来自同一篇文献时，系统应提示"以下分析主要基于单一研究，建议参考更多文献"
- 当用户请求的外推超出合理数据范围时（如"官能化程度 50%"），系统应拒绝外推并说明原因
- 当多个样本数据存在明显矛盾时，系统应明确列出不同数据及来源，并分析可能的差异原因（如实验条件、基体配方、测试方法不同），而非武断选择一方
- 当进行配方设计时，如果涉及安全或环保问题（如有毒试剂），系统应给出警示
- 当生成对比表格时，如果样本数量过少（< 2 个有效对比项），应退化为文字描述

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持综合 3-5 个相关样本的数据和结论生成整合性回答
- **FR-002**: 系统 MUST 在综合回答中明确标注每个数据点或建议的来源文献（使用文献引用格式，非样本ID）
- **FR-003**: 系统 MUST 支持基于多样本数据进行趋势分析和合理外推
- **FR-004**: 系统 MUST 在外推预测时明确标注"外推估计"，并使用三级置信度标签（高/中/低）+ 数据支撑点数说明（如"中等置信度，基于 4 个相近样本"）
- **FR-005**: 系统 MUST 在数据支撑不足时（相关样本 < 3 个）拒绝外推并说明原因；外推范围限制为数据覆盖范围外 50%（如数据覆盖 1%-15%，可外推到 0.5%-22.5%），超出则拒绝
- **FR-006**: 系统 MUST 支持根据用户目标性能需求生成配方设计建议
- **FR-007**: 系统 MUST 在配方建议中包含官能团选择、官能化程度、填料体系等核心参数
- **FR-008**: 系统 MUST 在检测到目标性能存在内在矛盾时，明确指出并给出折中建议
- **FR-009**: 系统 MUST 支持生成结构化对比表格，比较不同官能化方案
- **FR-010**: 系统 MUST 在数据缺失时在表格中标注"数据不足"，禁止编造数据
- **FR-011**: 系统 MUST 保持零幻觉原则——所有数值必须可追溯到具体文献
- **FR-012**: 系统 MUST 区分三类内容：①文献原始数据、②基于数据的分析结论、③外推预测
- **FR-013**: 系统 MUST 在回答中使用自然语言文献引用（如"根据 Zhang 等人的研究[1]"），不暴露数据库内部信息
- **FR-014**: 综合回答 MUST 采用分层结构：先给出结论摘要（2-3句话），再分点展开支撑证据和文献来源

### Key Entities

- **SynthesizedAnswer（综合回答）**: 基于多文献的整合性回答，包含：综合结论、数据来源列表、置信度标签、外推标记
- **TrendAnalysis（趋势分析）**: 从多样本数据中提取的规律，包含：变量关系描述、相关系数、适用范围、外推边界
- **ExtrapolationResult（外推结果）**: 基于趋势的预测值，包含：预测值、置信区间、数据支撑点数、不确定性说明
- **FormulaRecommendation（配方建议）**: 设计的配方方案，包含：官能团、程度、填料、预期性能、设计理由
- **ComparisonTable（对比表格）**: 结构化对比结果，包含：对比维度、各方案数据、数据来源、缺失标记

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 综合回答引用的文献数量 ≥ 2 篇（平均 3-5 篇）
- **SC-002**: 所有外推预测附带明确的不确定性说明，外推标注率 = 100%
- **SC-003**: 用户单次交互获得的有效信息量提升——综合回答覆盖的知识点数量比单样本回答多 50% 以上
- **SC-004**: 配方建议的参数完整性 ≥ 80%（官能团、程度、填料三要素至少有两项）
- **SC-005**: 对比表格的数据准确率 = 100%（所有数值可追溯到源文献）
- **SC-006**: 综合问答的响应时间 ≤ 8 秒（比单样本问答的 5 秒适当放宽）

## Assumptions

- 现有 67 个样本的 summary.md 提供了足够多样的官能化方案供综合分析
- 样本数据中包含足够的定量数据（如官能化程度与性能的对应关系）支持趋势分析
- GPT-4o 或更高级模型具备从多样本数据中提取规律和进行合理外推的能力
- 用户理解外推结果是基于有限数据的推测，不是实验验证的结论
- Prompt Engineering 可以有效控制模型的外推边界，防止过度自信的预测

## Out of Scope

- 实时查询外部数据库或论文库获取更多文献
- 自动执行分子模拟或性能预测计算
- 基于用户反馈的模型微调或主动学习
- 多轮对话式的配方迭代优化
- 成本估算或供应链分析
- 专利检索和侵权风险分析
