# 3. 系统设计与架构 (System Design and Architecture)

本章详细介绍 SSBR 官能化知识库系统的设计与实现。系统采用分层架构，从底层数据采集到上层智能问答形成完整的数据处理管道。

## 3.1 系统总体架构

### 3.1.1 模块化设计理念

系统设计遵循以下核心原则：

**（1）关注点分离（Separation of Concerns）**

系统划分为三个独立层次，各层职责清晰：
- **数据采集层**：负责文献获取、数据提取
- **数据处理层**：负责数据清洗、格式化、存储
- **RAG 检索层**：负责语义检索、问答生成

这种分层设计使得各模块可独立开发、测试和优化，降低了系统复杂度。

**（2）可扩展性（Extensibility）**

系统设计预留了多个扩展点：
- 新增官能团类型只需添加数据，无需修改代码
- 新增解读 Skill 可独立开发，符合统一输出格式即可接入
- 向量数据库可平滑升级（从 ChromaDB 到分布式方案）

**（3）可追溯性（Traceability）**

所有检索结果和生成内容均可追溯到原始文献：
- 每个数据点标注来源（DOI、表格编号、图注）
- 回答附带引用信息
- 支持审计和验证

## 3.2 知识库构建

知识库是整个系统的基础，其构建质量直接影响检索精度和回答可靠性。

### 3.2.1 文献数据采集与预处理

**（1）数据来源**

系统支持两种文献来源：
- **Zotero 文献管理**：优先级最高，通过 MCP（Model Context Protocol）集成
- **本地文献目录**：`literature/` 作为备选来源

每篇文献需包含：
- 主论文 PDF
- 补充材料（Supplementary Information, SI）
- DOI 标识符

**（2）AI 辅助数据提取**

采用大语言模型（豆包/Gemini/Claude）从 PDF 中提取结构化数据。提取流程如下：

```
PDF 文献 → AI 提取（提示词模板） → Markdown 表格 → 人工校验 → 导入系统
```

提示词模板（`other/解析数据的提示词.txt`）定义了提取字段和格式规范，确保输出一致性。提取的数据包括：
- 基本信息：作者、年份、DOI
- 官能化信息：官能团类型、试剂、程度
- 性能指标：力学性能、热学性能、动态性能

**（3）数据质量分级**

根据数据来源的可靠性，将数据分为三个层级：

| 层级 | 来源 | 置信度 | 示例 |
|------|------|--------|------|
| **L1** | 文献表格/正文数值 | 0.90-0.95 | "拉伸强度 18.5 MPa (Table 2)" |
| **L2** | 图面标注数字 | 0.85 | "Tg = -25°C (Fig. 3 标注)" |
| **L3** | 曲线视觉估读 | 0.50-0.75 | "应力 ~8 MPa @300% 应变 (估读)" |

这一分级机制贯穿整个系统，在回答生成时用于评估数据可靠性。

### 3.2.2 结构化数据模型设计（YAML Schema）

系统采用"元数据 + 解读文档"的双层数据模型：

**（1）元数据层（Excel）**

`dataset/数据.xlsx` 存储 24 列结构化元数据：

| 列范围 | 内容分类 | 代表字段 |
|--------|---------|---------|
| A-B | 标识信息 | 样本 ID、DOI |
| C-H | 官能化信息 | 试剂、官能团、程度、SMILES |
| I-N | 填料体系 | 白炭黑用量、偶联剂 |
| O-X | 性能指标 | 拉伸强度、Tg、tan δ |

Excel 格式便于人工编辑和数据验证，支持批量导入导出。

**（2）解读文档层（Markdown）**

每个样本目录（`dataset/interpretations/SSBR-XXX/`）包含五类解读文档：

```
SSBR-XXX/
├── mechanical.md    # 力学性能解读（应力-应变、Payne、DMA）
├── dsc.md          # 热学性能解读（DSC 分析）
├── nmr.md          # 核磁共振解读（结构表征）
├── tem.md          # TEM 形貌解读（填料分散）
└── summary.md      # 综合档案（RAG 检索核心）
```

每个解读文档采用 YAML Front Matter + Markdown 正文的格式：

```yaml
---
sample_id: SSBR-001
interpretation_type: mechanical
skill_used: ssbr-stress-strain-interpretation
created_at: 2026-03-15

data:
  tensile_strength:
    value: 18.5
    unit: "MPa"
    source: "Table 2"
  elongation:
    value: 420
    unit: "%"
    source: "Table 2"
---

# 力学性能解读

## 应力-应变特性

该样本表现出典型的弹性体应力-应变行为...
```

YAML Schema 定义了每种文档类型的必填字段、数值范围和格式规范（详见 `specs/002-rag-data-migration/contracts/yaml-schema.md`）。

### 3.2.3 元数据与解读文档分离策略

采用分离策略的设计考量：

| 维度 | 元数据（Excel） | 解读文档（Markdown） |
|------|----------------|---------------------|
| 数据类型 | 结构化数值 | 非结构化文本 |
| 查询方式 | 精确匹配、范围查询 | 语义检索 |
| 更新频率 | 低（人工录入） | 中（AI 生成） |
| 版本控制 | 困难 | Git 友好 |
| 适用场景 | 统计分析、数据导出 | RAG 检索、知识理解 |

这种分离实现了"结构化数据支撑精确查询，非结构化文档支撑语义理解"的双轨机制。

## 3.3 向量检索模块

向量检索是 RAG 系统的核心组件，负责根据用户查询召回相关文档。

### 3.3.1 文本嵌入方法

**（1）Embedding 模型选择**

系统采用 OpenAI 的 `text-embedding-3-small` 模型：

| 属性 | 值 |
|------|-----|
| 向量维度 | 1536 |
| 最大输入长度 | 8191 tokens |
| 语言支持 | 多语言（含中文） |
| API 调用成本 | $0.02 / 1M tokens |

选择该模型的理由：
- 中文性能优异，适合中文文献
- 维度适中，兼顾表达能力和存储效率
- API 稳定，便于集成

**（2）文本预处理**

输入 Embedding 前的预处理步骤：
1. 提取 Markdown 正文（去除 YAML Front Matter）
2. 去除特殊字符和冗余空白
3. 截断超长文本（保留前 8000 tokens）

**（3）向量化流程**

```python
def embed(text: str) -> List[float]:
    """将文本转换为 1536 维向量"""
    response = openai.Embedding.create(
        input=text,
        model="text-embedding-3-small"
    )
    return response['data'][0]['embedding']
```

### 3.3.2 ChromaDB 向量数据库设计

**（1）ChromaDB 选型理由**

在多种向量数据库中选择 ChromaDB 的考量：

| 特性 | ChromaDB | Pinecone | FAISS |
|------|----------|----------|-------|
| 部署方式 | 本地嵌入 | 云托管 | 本地 |
| 持久化 | ✅ | ✅ | 需额外实现 |
| Python 集成 | 原生 | SDK | 需封装 |
| 学习曲线 | 低 | 中 | 高 |
| 适用规模 | 中小型 | 大型 | 任意 |

对于 68 个样本的规模，ChromaDB 完全满足需求，且部署简单、无需云服务依赖。

**（2）数据库结构**

ChromaDB 集合（Collection）设计：

```python
collection = chroma_client.create_collection(
    name="ssbr_summaries",
    metadata={"hnsw:space": "cosine"}  # 使用余弦相似度
)

# 添加文档
collection.add(
    documents=[summary_content],
    embeddings=[embedding_vector],
    metadatas=[{"sample_id": "SSBR-001", "path": "..."}],
    ids=["SSBR-001"]
)
```

**（3）存储位置与同步策略**

- 存储路径：`.cache/chroma_db/`
- 不纳入 Git 版本控制（.gitignore）
- 跨设备需运行 `python scripts/build_vector_cache.py --force` 重建

### 3.3.3 HNSW 近似最近邻算法

ChromaDB 内置 HNSW（Hierarchical Navigable Small World）索引，实现高效的近似最近邻搜索。

**（1）HNSW 原理**

HNSW 构建多层图结构：
- **顶层**：稀疏图，节点少，边长（支持快速跳跃）
- **底层**：稠密图，节点多，边短（支持精确定位）

查询时从顶层进入，逐层下降，在每层执行贪心搜索，最终在底层找到近邻。

**（2）复杂度分析**

| 操作 | 时间复杂度 |
|------|-----------|
| 构建索引 | $O(n \log n)$ |
| 查询 | $O(\log n)$ |
| 插入 | $O(\log n)$ |

**（3）性能实测**

在 68 个样本的数据集上：

| 指标 | 数值 |
|------|------|
| 索引构建时间 | ~2 秒 |
| 单次查询延迟 | ~5 ms |
| 内存占用 | ~10 MB |

相比暴力搜索的 $O(n)$ 复杂度，HNSW 在大规模数据集上优势更为明显。

## 3.4 重排序模块

两阶段检索策略中，重排序模块负责对初筛结果进行精细排序。

### 3.4.1 交叉编码器（Cross-Encoder）原理

**（1）双编码器 vs 交叉编码器**

| 特性 | 双编码器（Bi-Encoder） | 交叉编码器（Cross-Encoder） |
|------|----------------------|---------------------------|
| 输入方式 | 分别编码 query 和 doc | 拼接后联合编码 |
| 交互建模 | 无 | 充分 |
| 计算效率 | 高（可预计算 doc） | 低（需实时计算） |
| 排序精度 | 中 | 高 |
| 适用场景 | 召回（大规模） | 重排（小规模） |

系统采用"双编码器召回 + 交叉编码器重排"的两阶段策略，兼顾效率和精度。

**（2）交叉编码器计算过程**

给定查询 $q$ 和文档 $d$，交叉编码器计算相关性分数：

$$
\text{score}(q, d) = \sigma(W \cdot \text{BERT}([CLS] + q + [SEP] + d + [SEP]))
$$

其中 $\sigma$ 为 sigmoid 函数，$W$ 为可学习参数。

### 3.4.2 BGE-Reranker-Base 模型应用

**（1）模型简介**

系统采用 BAAI（北京智源研究院）开源的 `bge-reranker-base` 模型：

| 属性 | 值 |
|------|-----|
| 模型大小 | ~1.1 GB |
| 基础架构 | BERT-base |
| 最大长度 | 512 tokens |
| 中文支持 | ✅ |

**（2）实现代码**

```python
class Reranker:
    DEFAULT_MODEL = "BAAI/bge-reranker-base"
    
    def rerank(self, query: str, candidates: List[Candidate], top_k: int = 3):
        # 构造 query-document pairs
        pairs = [(query, c.content) for c in candidates]
        
        # 获取重排分数
        scores = self._model.predict(pairs)
        
        # 按分数排序
        results = sorted(zip(candidates, scores), key=lambda x: x[1], reverse=True)
        return results[:top_k]
```

**（3）质量感知重排**

在基础重排分数上叠加样本质量评分：

$$
\text{FinalScore} = \text{RerankScore} + \alpha \cdot \text{QualityScore}
$$

其中 $\alpha = 0.1$ 为质量权重，QualityScore 基于 24 列元数据的完整率计算：

$$
\text{QualityScore} = \frac{\text{已填写字段数}}{24}
$$

这一机制确保数据完整的样本获得更高排名，避免推荐数据残缺的结果。

### 3.4.3 两阶段检索效果评估

表 3-1 对比了不同检索策略的效果：

**表 3-1 检索策略效果对比**

| 策略 | Hit Rate@3 | Hit Rate@5 | 平均延迟 |
|------|-----------|-----------|---------|
| 纯向量检索 | 75.0% | 83.3% | 50 ms |
| + 交叉编码器重排 | 83.3% | 91.7% | 200 ms |
| + 质量感知降权 | 83.3% | 91.7% | 210 ms |

## 3.5 问答生成模块

问答生成模块将检索结果转化为用户可读的自然语言回答。

### 3.5.1 Prompt 工程设计

**（1）三级回答类型**

根据最高相似度分数，系统生成三种类型的回答：

| 相似度 | 回答类型 | 特点 |
|--------|---------|------|
| ≥ 0.7 | DIRECT | 直接回答，高置信度，引用具体数值 |
| 0.5-0.7 | REFERENCE | 参考回答，标注"仅供参考" |
| < 0.5 | GUIDANCE | 引导性建议，提供通用技术方向 |

**（2）System Prompt 设计原则**

System Prompt 遵循以下原则：
- **零幻觉原则**：所有数值必须来自样本数据，禁止编造
- **直接回答优先**：第一句话必须直接回答问题核心
- **引用规范**：使用官能团类型描述方案，禁止暴露内部样本 ID

示例 System Prompt（DIRECT 类型）：

```
你是一位 SSBR 官能化改性领域的专家。

## 回答规范

1. 忠实于上下文：回答中的具体数值必须来自样本信息
2. 直接回答优先：第一句话必须直接回答用户问题的核心
3. 简洁性要求：回答长度控制在 200-350 字
4. 引用规范：使用官能团名称描述方案（禁止直接展示样本 ID）
```

**（3）User Prompt 模板**

User Prompt 包含三部分：
1. 用户原始问题
2. 检索到的样本信息（包含结构化元数据和正文内容）
3. 回答格式要求

```
## 用户问题
{query}

## 检索到的相关样本
### 方案 1: 羟基官能化
**相关度**: 0.85 | **数据完整度**: 92%
...

## 回答要求
请基于以上样本信息，生成一个专业、准确的回答：
1. 使用官能团名称描述方案
2. 综合多个样本的信息
3. 回答长度 400-500 字
```

### 3.5.2 回答质量控制

**（1）长度控制**

不同回答类型有不同的长度要求：

| 类型 | 目标长度 | 允许范围 |
|------|---------|---------|
| DIRECT | 400-500 字 | 350-600 字 |
| REFERENCE | 300-400 字 | 250-500 字 |
| GUIDANCE | 200-300 字 | 150-400 字 |

**（2）引用验证**

回答生成后进行引用验证：
- 检查是否所有数值都能在样本中找到来源
- 检查是否存在样本 ID 泄露
- 计算引用追溯率（目标 ≥ 80%）

**（3）置信度标注**

所有推断性内容需标注置信度：
- 高置信度：数据直接来自 L1 来源
- 中置信度：数据来自 L2/L3 来源或多样本推断
- 低置信度：外推预测或单一样本

### 3.5.3 输出格式规范

问答系统输出包含多个结构化组件：

**（1）推荐方案卡片**

```markdown
🎯 推荐方案

| 参数 | 推荐值 | 置信度 |
|------|--------|--------|
| **推荐官能团** | 羟基 (-OH) | 高 |
| **推荐试剂** | 3-巯基丙醇 | 高 |
| **推荐官能化程度** | 2.5-4.0 wt% | 中 |
| **预期效果** | Payne 效应降低 30-50% | 中 |
```

**（2）自然语言回答**

300-500 字的专业回答，包含数据引用和技术分析。

**（3）文献引用**

```markdown
📚 数据来源

[1] Zhang et al., Polymer, 2024 (DOI: 10.1016/j.polymer.2024.xxx)
[2] Wang et al., Macromolecules, 2023 (DOI: 10.1021/acs.macromol.2023.xxx)
```
