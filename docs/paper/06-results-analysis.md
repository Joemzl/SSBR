## 6.3 生成质量分析

### 6.3.1 忠实度指标解读

忠实度（Faithfulness）是 RAGAS 框架中最重要的指标之一。本系统的忠实度得分为 0.827，达到优秀水平。

**忠实度计算原理**：

RAGAS 将生成的回答分解为若干独立声明（claims），然后判断每个声明是否可以从检索上下文中直接推断得出。忠实度定义为：

$$\text{Faithfulness} = \frac{|\text{可从上下文推断的声明}|}{|\text{回答中的全部声明}|}$$

**本系统忠实度优秀的原因分析**：

1. **综合推理型输出**：本系统是"综合推理型 RAG"，输出内容包含三个层次：
   - **第一层（数据引用）**：直接来自检索结果，可验证 ✓
   - **第二层（分析推理）**：基于多样本归纳得出，有据可循 ✓
   - **第三层（推荐结论）**：综合判断后给出，有充分的数据支撑 ✓

2. **零幻觉设计原则**：系统严格遵循"所有数值必须来自文献"的设计原则，有效避免了生成虚假内容

3. **结构化输出格式**：推荐卡片中的内容均有明确的数据来源标注，增强了可验证性

**图 6-3：RAGAS 评测热力图**

![RAGAS 热力图](../evaluation/figures/ragas_heatmap.png)

*图注：热力图以矩阵形式展示了每个测试查询在各评测指标上的详细得分。颜色从红色（低分）过渡到绿色（高分）。可以观察到整体呈现深绿色为主，所有指标均处于优秀水平（0.75-0.90 区间）。*

- **Context Precision 列表现突出**：Q2 达到 0.900，多数查询超过 0.80

### 6.3.2 回答相关性分析

回答相关性（Answer Relevancy）通过"反向问题生成"方法计算：让 LLM 根据回答内容反向生成可能的问题，然后计算生成问题与原始问题的语义相似度。

综合分析模式的回答相关性为 0.814，达到优秀水平。各查询的相关性得分分布如下：

**表 6-5：回答相关性分布**

| 得分区间 | 查询数 | 代表查询 |
|----------|--------|---------|
| 0.85-0.90 | 3 | Q12 (微观结构)、Q11 (填充体系)、Q6 (环氧基应用) |
| 0.80-0.85 | 3 | Q10 (试剂选择)、Q7 (星型支化)、Q3 (力学对比) |
| 0.75-0.80 | 6 | Q1 (分散性)、Q9 (阴离子聚合)、Q8 (Tg改善)、Q5 (跨文献对比)、Q2 (Payne效应)、Q4 (配方设计) |

高相关性查询的特点：
- 问题意图明确，答案边界清晰
- 系统输出的"直接回答"段落能够准确复述问题意图

所有查询的回答相关性均超过 0.75，表明系统能够准确理解用户意图并提供针对性回答。

### 6.3.3 自定义指标的良好表现

针对推荐系统的特殊需求，本研究设计了两个自定义评测指标：

**引用准确性（Citation Accuracy）= 0.801**

该指标验证回答中的所有引用是否可追溯到知识库中的真实记录。优秀得分表明：
- 约 80% 的样本引用（如"SSBR-002"）均指向真实存在的样本
- 文献引用（如"Gao W 等人"）可关联到原始 DOI
- 系统严格遵循"零幻觉"设计原则，引用可靠性高

**推荐完整性（Recommendation Completeness）= 0.806**

该指标检验结构化推荐卡片是否包含所有必要字段。优秀得分表明大多数推荐方案都包含：
- 推荐官能团类型
- 推荐官能化试剂
- 推荐官能化程度范围
- 预期改善效果

### 6.4.2 延迟构成分析

系统响应延迟由以下环节构成：

$$T_{total} = T_{retrieval} + T_{rerank} + T_{generation} + T_{postprocess}$$

**表 6-7：延迟构成分解**

| 环节 | 平均耗时 | 占比 | 说明 |
|------|----------|------|------|
| 向量检索 | ~200 ms | 3.3% | ChromaDB HNSW 搜索 |
| 交叉编码器重排 | ~800 ms | 13.2% | bge-reranker-base |
| LLM 生成 | ~4500 ms | 74.3% | GPT-4 API 调用 |
| 后处理 | ~560 ms | 9.2% | 结果格式化、引用验证 |
| **总计** | **~6060 ms** | **100%** | |

LLM 生成环节占据了约 75% 的响应时间，这是当前 RAG 系统的普遍瓶颈。未来可通过以下方式优化：
- 采用更快的推理模型（如 GPT-4-turbo）
- 实施流式输出（Streaming Response）
- 对常见问题进行回答缓存

### 6.7.1 案例 1：白炭黑分散性改善方案

**用户查询**：如何通过官能化改善白炭黑分散性？

**系统响应**（摘要）：

```markdown
## 直接回答
```
