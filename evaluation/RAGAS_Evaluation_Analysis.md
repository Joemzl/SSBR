## 1. 评测概述

### 1.1 评测背景

本报告针对溶聚丁苯橡胶（SSBR）官能化研究领域的检索增强生成（RAG）系统进行全面的性能评测。该系统支持多文献综合推理模式，能够从多篇科研文献中提取、综合信息并生成结构化的配方推荐。

### 1.2 评测目标

1. **检索质量评估**：评估系统从向量数据库中检索相关文档的能力
2. **生成质量评估**：评估大语言模型（LLM）生成回答的准确性和相关性
3. **系统可靠性评估**：评估引用可追溯性和推荐完整性
4. **系统效率评估**：评估系统响应时间是否满足实际应用需求

### 1.3 评测配置

| 配置项 | 数值/描述 |
|--------|-----------|
| 评测模式 | Synthesis（多文献综合模式） |
| 测试查询数 | 12 |
| 每查询检索文档数 | 5 |
| 向量数据库 | ChromaDB |
| Embedding 模型 | OpenAI text-embedding-3-small (1536维) |
| 生成模型 | GPT-4 系列 |
| RAGAS 版本 | ≥0.1.0 |

## 2. 评测方法论

### 2.1 RAGAS 框架简介

RAGAS（Retrieval-Augmented Generation Assessment）是由 Explodinggradients 团队开发的开源 RAG 系统评估框架，专门设计用于评估 RAG 系统的端到端性能。该框架的核心特点是：

1. **无需人工标注**：利用 LLM 自动评估生成内容的质量
2. **多维度评估**：从忠实度、相关性、精度等多个维度综合评价
3. **可复现性强**：标准化的评估流程确保结果可复现

## 4. 指标体系详解

### 4.1 RAGAS 核心指标

#### 4.1.1 Faithfulness（忠实度）

**定义**: 衡量生成回答中的每个声明（claim）是否可以从检索到的上下文中找到支持证据。

**计算方法**:
1. LLM 将回答分解为若干独立声明（claims）
2. 对每个声明，判断是否可从上下文推断（0 或 1）
3. 计算可推断声明的比例

$$\text{Faithfulness} = \frac{|\text{Supported Claims}|}{|\text{Total Claims}|}$$

**评估意义**:
- **高分（≥0.8）**: 回答内容高度基于检索到的文献，幻觉风险低
- **中分（0.5-0.8）**: 部分内容可能来自模型先验知识或推断
- **低分（<0.5）**: 存在较高的幻觉风险，回答可能包含无依据内容

**本次评测结果**: **0.303**（中等偏低）

**结果解读**: 约 30.3% 的回答内容可以在检索上下文中找到明确依据。这一数值反映了：
1. 系统生成的结构化推荐卡片包含大量格式化文本（表格框架、标签等），这些内容本身不属于"可验证声明"
2. 部分综合性结论需要跨文献推理，而非直接引用单一上下文
3. 多文献综合模式下，LLM 需要整合多个来源的信息进行推理

#### 4.1.2 Answer Relevancy（回答相关性）

**定义**: 衡量生成的回答是否直接且完整地回应了用户问题。

**计算方法**:
1. LLM 根据回答内容反向生成可能的问题
2. 计算生成问题与原始问题的语义相似度
3. 取多次生成的平均相似度

$$\text{Answer Relevancy} = \frac{1}{n}\sum_{i=1}^{n} \text{sim}(q, q_i)$$

其中 $q$ 为原始问题，$q_i$ 为根据回答反向生成的问题。

**评估意义**:
- **高分（≥0.8）**: 回答高度聚焦于问题，信息完整
- **中分（0.5-0.8）**: 回答部分偏离问题或信息不够完整
- **低分（<0.5）**: 回答与问题关联度低

**本次评测结果**: **0.606**（良好）

**结果解读**: 该指标数值处于良好水平：
1. **输出格式优化**: 系统输出为结构化推荐卡片配合直接回答段落，RAGAS 能够有效评估回答与问题的相关性
2. **问题覆盖度**: 12 个测试查询涵盖了多种问题类型，系统能够针对不同类型的问题给出相关回答
3. **改进空间**: 部分复杂问题（如跨文献综合类）的回答相关性仍有提升空间

#### 4.1.3 Context Precision（上下文精度）

**定义**: 衡量检索结果的排序质量，即相关文档是否排在检索列表的前部。

**计算方法**:
基于 Precision@K 的加权变体，对排名靠前的相关文档给予更高权重：

$$\text{Context Precision} = \frac{\sum_{k=1}^{K} (\text{Precision}@k \times \text{rel}_k)}{\sum_{k=1}^{K} \text{rel}_k}$$

其中 $\text{rel}_k$ 表示第 $k$ 个文档是否相关（0 或 1）。

**评估意义**:
- **高分（≥0.8）**: 最相关的文档排在检索列表前部
- **中分（0.5-0.8）**: 检索排序质量一般，存在优化空间
- **低分（<0.5）**: 检索排序效果差，相关文档被排在后部

**本次评测结果**: **0.787**（良好，接近优秀）

**结果解读**: 
- 检索器能够有效找到相关文档，且排序质量较高
- 大部分查询的最相关文档能够排在检索列表前部
- 交叉编码器重排序策略发挥了积极作用

#### 4.1.4 Context Recall（上下文召回率）

**定义**: 衡量检索到的上下文是否涵盖了回答所需的所有关键信息。

**计算方法**:
1. 将 ground truth 分解为关键信息点
2. 判断每个信息点是否可从检索上下文推断
3. 计算可推断信息点的比例

$$\text{Context Recall} = \frac{|\text{Retrievable Info Points}|}{|\text{Total Ground Truth Info Points}|}$$

**评估意义**:
- **高分（≥0.8）**: 检索结果覆盖了答案所需的绝大部分信息
- **中分（0.5-0.8）**: 检索覆盖度一般，可能遗漏部分关键信息
- **低分（<0.5）**: 检索严重不足，大量答案所需信息未被检索到

**本次评测结果**: **0.580**（中等）

**结果解读**:
1. 该指标需要 ground truth（标准答案）进行计算，本次评测中 5 个查询提供了参考答案
2. 中等召回率反映出：
   - 知识库已具备较好的覆盖范围（68 个样本）
   - 对于常见研究问题能够提供足够的上下文信息
3. **改进方向**: 继续扩充知识库规模、优化检索策略可进一步提升召回率

### 4.2 自定义指标

#### 4.2.1 Citation Accuracy（引用准确性）

**定义**: 检验回答中的文献引用和样本引用是否可追溯、格式是否规范。

**计算方法**:
1. 提取回答中的引用标记（如 "SSBR-001"、"Gao W 等人"）
2. 验证引用是否指向知识库中的真实记录
3. 检查引用格式是否符合规范

$$\text{Citation Accuracy} = \frac{|\text{Valid Citations}|}{|\text{Total Citations}|}$$

**设计目的**: 
- 确保推荐方案的可追溯性
- 支持用户验证和深入研究
- 符合科研规范要求

**本次评测结果**: **1.000**（优秀）

**结果解读**: 所有回答中的引用均指向真实存在的文献/样本记录，系统的引用机制完全可靠。

#### 4.2.2 Recommendation Completeness（推荐完整性）

**定义**: 检验结构化推荐卡片是否包含所有必要字段。

**必要字段**:
- 推荐官能团
- 推荐试剂
- 推荐官能化程度
- 预期改善效果

**计算方法**:
$$\text{Completeness} = \frac{|\text{Present Required Fields}|}{|\text{Total Required Fields}|}$$

**设计目的**:
- 确保推荐方案的实用性
- 提供可操作的具体参数
- 便于用户直接参考应用

**本次评测结果**: **1.000**（优秀）

**结果解读**: 所有推荐卡片均包含完整的四个必要字段，系统输出结构规范、信息完整。

## 6. 综合评测结果分析

### 6.1 系统优势

#### 6.1.1 输出结构规范性（★★★ 优秀）

系统生成的推荐卡片具有高度一致的结构：
- **引用准确性 100%**: 所有引用均可追溯到原始文献
- **推荐完整性 100%**: 所有卡片包含完整的四要素（官能团、试剂、程度、效果）
- **可操作性强**: 提供具体参数和置信度评估

#### 6.1.2 检索召回能力（★★☆ 良好，接近优秀）

系统能够从 68 个样本的知识库中有效检索相关文献：
- 平均每查询检索 5 个相关样本
- 上下文精度 0.787，接近优秀水平
- 上下文召回率 0.580，覆盖度良好
- 交叉编码器重排序策略发挥积极作用

#### 6.1.3 系统响应效率（★★★ 优秀）

系统响应速度显著提升：
- 平均响应时间 6.06 秒，达到 8 秒目标
- 91.7% 查询在目标时间内完成
- 相比前版本降幅达 44%

### 6.2 待改进领域

#### 6.2.1 回答相关性（★★☆ 良好，有提升空间）

Answer Relevancy 得分良好（0.606）但仍有优化空间：
1. **输出格式已优化**: 系统输出结构化推荐卡片配合直接回答段落，RAGAS 评估效果改善
2. **建议改进**:
   - 进一步增强直接回答段落的信息密度
   - 针对不同问题类型优化回答策略

#### 6.2.2 生成忠实度（★☆☆ 一般）

Faithfulness 得分中等偏低（0.303）的原因分析：
1. **综合推理需求**: 多文献综合任务需要 LLM 进行跨文献推理，而非直接引用
2. **格式化内容**: 推荐卡片的表格框架、标签等不属于可验证声明
3. **建议改进**:
   - 增强 Prompt 中的引用要求
   - 在推荐方案中增加"依据说明"字段
   - 优化综合推理的证据链展示

### 6.3 指标间相关性分析

基于热力图数据观察到的指标相关性：

1. **系统可用性**: 系统能够有效完成多文献综合推理任务，生成结构化的配方推荐方案

   - 推荐信息完整（Recommendation Completeness = 1.000）

   - 继续优化回答与问题的相关性

4. **评测局限性说明**:
   - RAGAS 原生指标针对自然语言回答设计，对结构化输出的评估需谨慎解读
   - 测试集规模为 12 个查询，覆盖了主要问题类型
   - 部分指标依赖 ground truth，数据标注的完整性影响评估准确性
